Задача:
В ручную распределить фотогафии по папкам
Фотографии скачиваются в виде архива, по нажатии кнопки скачать на сайте

Сделать GUI которая упростит задачу:
1. нужен функционал для скачивания, который будет скачивать не отсортированные архивы, разорхивировать их и отправлять в папку не отсортированных фото
в архиве 3 папки которые содержат уникальные фото: out, no-events, in. Добавить промежуточный этап выбора из каких папок брать фотогафии + название кампании,
затем программа пройдется по
выбранным папкам и отправит все фото в общую папку не отсортированных фото, где фото так же распределены по папкам, но уже в соответствии с названием кампании,
без сохранения былой структуры( папок аут, но ивентс, ин). Название фото поменять на "название компании" + старое название" 





ПОдсчет кол-во добавленных фото дяля каждой категории
GUI 2.0

0?. Функционал регистрации. При регестрации выбор одной из ролей, 1 - все что он может это сортировать показанные ему фото, 2 - тот кто может делать все.
Для создания юзера с ролью 2 нужно ввести секретный ключ.

1. Функционал рабочих окружений, выбор проекта из списка и продолженние работы с ним, либо создание нового. При нажатии на создать новый, предлагается заполнить форму,
пока что из названия проекта, напримр распределение взрослых и детей по папкам, плюс написать категории для распределения, max 20 штук. Опираясь на категории будут
созданы папки, 1 категория == 1 папка с соответсвутющим именем. У каждого проекта в своей родительнской папке, есть 2 основные папки, sorted и unsorted,
сама род папка создается с названием проекта в момент создания проекта.

2. Основной функционал распределения фотографий по папкам:
Распределение по папкам ( категориям) не отсортированных фотографий. На каждом этапе показывается сама фотография и снизу категории для выбора, к примеру ребенок,
взрослый. После выбора фото отправляется в нужную папку, вызывается весь нужный функционал для обработки этого события, обновления счетчиков в бд и так далее,
помещается как отсортированный и так далее.
Возможность отката на 3 фотографии назад, в таком случае 3 последних фото отправятся обратно в unsorted. В соответсвии с этим обновится вся инфа в базе данных,
а сами 3 последних фото хранятся в кеше, поэтому после перезагрузки программы возможности откатится нет.
Перед тем как фото отправится на показ кому то для сортировки, оно помещается как "выбранный" для того что бы одна фотогафия не была отправленна двум людям.
Некий атрибут selected в Модели Photo. Плюс таймер когда он был помечен как selected. По истечению 10 минут selected становится равной False. фоновая задача, например
celery, запускается раз в 30 минут.

3. Функционал для добавления нового архива с фото. Нужна возможность добавления новой партии фотографий в папку unsorted соответсвующего проекта. Так же заполняется
форма, ввести название обьекта откуда взят архив, даты и  выбор архива локально или в будущем скачивание с интернета ( то есть ссылка). Так же ввести список всех 
добавленных архивов ( для каждого проекта свой), с их информацией, и возможностью сбора статистики в будущем.
Функционал добавления нового архива, например локального, будет разорхивировать его и оправлять фотографии оттуда в папку unsorted соответствующего проекта.

У каждого проекта свой счетчик не отсортированнных фотографий, счетчик отсортированных. Так же при желании детально рассмотреть разброс по категориямЮ для каждой из
них тоже свой счетчик.
Возможно стоить юзать sqlite что бы эти счетчики не сбивались при перезапуске программы.




стек технологий:

Архитектура бэка: DDD, абстрактые сервисные слои. Сервисный слой работает с доменой областью. Вьюхи вызывают UseCase которые могут в себе содержат сервисные слои
как атрибуты и работают с ними.
Необходимо логировать все действия. К примеру модель auditlog





Важно что бы вся система не сломались при ручном удалении, перемещении или добавлении фотографий между категориями в папке sorted. Не страшно если собьются подсчеты
главное отсутствие других системных ошибок.
